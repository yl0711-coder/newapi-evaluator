# API 中转站测试平台

内部使用的渠道准入、持续评测与运营证据平台。它只读取生产指标、形成技术建议，不自动写中转站配置，不自动改变生产路由，也不根据数据自行修改代码。

## 评测规则

评测体系以 `app/test_catalog.py`、`app/evaluation_packs.py` 和 `app/grading.py` 为实现真源；独立硬题题面保存在 `app/hard_items.json`。

## 已实现闭环

### 极简接入与评测

- 五步准入向导：粘贴连接信息、选择意向平台组、发现并确认模型、选择专项、查看动态请求数/时间/费用后提交。
- 支持 JSON、curl、`KEY=VALUE`、普通文本以及常见字段别名；明文 Key 不回显。
- 默认模型家族和模型包可在工作台维护；支持显示名、排序、启停、实验/启用/观察/弃用/退役、替代模型和归档。
- 支持规范模型 ID、精确别名与模糊候选；模糊匹配必须人工确认，模型名和行为指纹均不用于承诺真实上游身份。
- 基础准入决定可用性；Agent、编程、客服专项可不选、单选或多选，只生成用途标签，不互相否定。
- 基础步骤与多个专项自动去重；每次任务保存不可变计划快照和各包版本。
- 基础报告直接展示智力题是否达到 5/6、全部流式题稳定率，以及固定速度题的首字和完整响应 P50/P95；专项测试保持手动、独立展示。

当前基础题库版本、题量和请求数以 `/api/admission-plan-preview` 与 `/api/estimate` 返回值为准，页面不再硬编码。能力评测可选独立 HardcoreLogic 硬题；硬题独立计分，不进入四维能力分、可用性、超时率或延迟门槛。双端渠道对比使用同一题面变体逐题并发执行，分别完成基础准入后再比较能力和固定速度。

### 技术分组与生命周期

- 工作台一级为“模型家族 + 平台上线倍率”，二级为“渠道 + 上游采购倍率”。同一模型只有一个当前归属，改组是移动而非复制。
- 每个平台组按实际模型维护独立标杆槽位；标杆要求结果完整、模型一致且题库版本一致。
- 准入先判断用户选择的意向组；未达到时，再用同一次、同模型、同题库版本结果比较同家族其他有效技术组。
- 建议可以是原组、其他组、观察池或拒绝；只有人工确认后才改变归属。
- 上游采购倍率只展示，不参与技术推荐；平台不计算利润或替代商业判断。
- 模型、渠道、家族和平台组使用生命周期/归档，历史任务、报告和标杆来源继续可追溯。

### 生产洞察

- 通过版本化只读接口按游标拉取批量分钟桶，支持重复拉取和乱序覆盖，不读取生产数据库。
- 指标包含平台组、规范模型、用途、实际渠道、请求/尝试/成功/失败/重试/切流、分类错误、Token、TTFT、延迟、生成速度、输出长度、匿名活跃用户与头部集中度。
- 协议出现 Prompt、Key、完整响应或原始用户 ID 时整页拒绝。
- 用户、令牌或分组的主用途与多个次用途由运营人员显式配置；录入标识立即转为部署内不可逆 HMAC 指纹，数据库和导出接口均不保存原值。
- 分钟数据保留 30 天，小时聚合保留 180 天，日级趋势保留 2 年。
- 页面提供实时健康、数据新鲜度、需求前三、同模型稳定前三、同模型/用途/输出长度速度前三、低样本说明和周度供给缺口。
- 高需求或关键用途以 3 路低相关合格渠道为目标，普通需求以 2 路为目标；疑似同故障域只作为提示。
- 新渠道上线后支持 7 天和 30 天效果复盘，比较成功率、P95、切流与集中度，不因一次波动自动修改规则。

生产指标使用独立 `metrics.db`，账号、任务、审计等使用 `platform.db`。旧单库指标会在首次启动时复制到独立库，旧表仅留作回滚，不再写入。

## 异常归因

- 监测平台通过 HMAC-SHA256 签名 Webhook 推送事件，签名正文为 `timestamp.raw_body`，允许 5 分钟时差。
- 事件 ID 幂等；同渠道、同模型、短时间窗告警自动合并。
- 收集告警窗口分钟指标、平台配置变更、已验签告警携带的匿名路由尝试链，以及生产/独立网络位置的专用轻量探针。
- 匿名路由链最多 500 条、每链最多保留 50 次尝试，保留 30 天；出现原始用户 ID、Prompt、Key、Token 或完整正文时整条告警拒绝。
- 探针受每小时频率、超时、并发与费用边界约束；第二位置离线会降低置信度。
- 输出最可能原因、置信度、支持证据、反证、影响范围、建议动作和人工复核要求。
- 不自动停用渠道、不改路由权重、不封禁用户。

## 本地压力测试执行器

云端主应用强制禁止执行压力测试。网页只负责创建任务并选择在线执行器：

1. 网页生成一次性配对码。
2. `local_runner.py` 在用户电脑生成 X25519/Ed25519 密钥并主动配对、轮询领任务。
3. 云端把短期任务凭据用执行器公钥加密；Key 只在本地执行器内存短暂存在，不写磁盘。
4. 执行器完成闭环或开环负载并签名回传，云端验证执行器、任务 ID、签名和重复结果。
5. 报告包含成功率、吞吐、P50/P95/P99、TTFT、tokens/s、衰减、安全并发、缓存疑点，以及 CPU、网络、调度和发生器饱和度。

执行器离线、版本过旧或未配对时不能提交；绝不自动回落到云服务器。页面实际档位和每档请求数会实时传给 `/api/estimate`，不使用静态 60 次估算。

## 上线确认与飞书

流程固定为：测试证据 → 用户确认技术建议 → 生成不含 Key 的配置草案 → 人工在中转站上线 → 只读接口按业务 ID 核验在线状态和模型 → 预览飞书差异 → 用户确认同步。

- 中转站是实际上线状态的事实来源；测试平台不写生产配置。
- 飞书使用“渠道表 + 模型映射表”，按业务 ID 幂等 Upsert。
- 同步内容包含脱敏域名、倍率、状态、时间、负责人、规范模型、家族、技术组、生命周期、准入/专项标签、版本、标杆和报告链接。
- 不同步 Key、完整敏感查询参数或原始错误响应。
- 手工修改冲突会显示差异并等待确认，不反向覆盖业务系统。
- 写入失败进入独立 Outbox 指数重试；失败不回滚中转站上线状态。

## 账号、安全与可靠性

- 内部人员使用独立账号，当前业务权限相同；支持登录、退出、改密和停用账号。
- 密码使用 scrypt 慢哈希；登录按账号和来源限流；会话 Cookie 为 HttpOnly、SameSite=Strict，HTTPS 部署强制 Secure。
- 所有业务页面需登录；所有写接口校验 CSRF。
- 写操作记录操作人、时间、对象、结果和脱敏的变更前后摘要；审计支持按人员、时间、对象、动作和结果筛选。
- Key、SMTP 密码、飞书凭据、Webhook 密钥和执行器临时凭据加密保存；报告、事件和错误只保存脱敏内容。
- 出站默认只允许 HTTP/HTTPS 公网；私网、回环、链路本地、保留地址和云元数据默认拒绝。DNS 解析和每次重定向均复验，最多 3 次重定向，非流式响应默认最多 8 MiB。
- 私网白名单仅由部署者通过 `TEST_EGRESS_ALLOWLIST` 精确配置主机名、IP 或 CIDR，不支持通配符，也不开放网页动态放行。
- 任务使用数据库租约、心跳和到期回收防止双执行。尚未开始的排队任务重启后恢复；执行器异常使用指数退避，连续失败进入失败队列并生成后台告警。
- 每日计划具有数据库幂等键；飞书同步使用独立 Outbox。
- 调度器异常不再静默吞掉，会进入“运营设置 → 后台健康告警”。
- 任务支持负责人、标签、运营备注和未审查/审查中/已通过/已驳回状态及组合搜索。
- 90 天前的报告会 gzip 压缩归档，打开、导出和历史结论保持不变。

## 加密备份与恢复

- 每日按 UTC 调度业务库和指标库的 SQLite 在线快照。
- 两个快照与 SHA-256 清单打包后使用独立 Fernet 密钥加密，仅生成 `.backup.enc`。
- 恢复演练在临时目录解密，验证文件清单、哈希和 `PRAGMA integrity_check`，不会覆盖当前数据库。
- “运营设置”显示备份记录、是否配置服务器外路径、两库容量和 PostgreSQL 迁移阈值。
- 生产必须把 `TEST_BACKUP_DIR` 和 `TEST_BACKUP_KEY_PATH` 挂载到服务器之外的私有位置；默认本地路径只用于开发并会明确提示未达异地要求。
- 任一 SQLite 默认达到 1 GiB 时提示迁移 PostgreSQL，可用 `TEST_SQLITE_MIGRATION_BYTES` 调整。

## 运行

本机开发：

```powershell
python -m pip install -r requirements.txt
python manage_accounts.py add <用户名>
python manage_accounts.py list
python manage_accounts.py disable <用户名>
python manage_accounts.py enable <用户名>
python run.py
```

默认仅监听 `127.0.0.1:8000`。账号密码不写入源码；也可在首次部署时提供 `TEST_BOOTSTRAP_USERNAME` 和 `TEST_BOOTSTRAP_PASSWORD`。

### 一键渠道快照

测试机先在本机安全环境中设置 `CHANNEL_SNAPSHOT_CONFIG`，使其指向仓库外的渠道配置文件。文件复用现有导入格式，支持 JSON、`KEY=VALUE`、curl 或普通文本。也可以由密钥管理器注入 `CHANNEL_SNAPSHOT_INPUT`，或分别注入 `CHANNEL_SNAPSHOT_ALIAS`、`CHANNEL_SNAPSHOT_BASE_URL`、`CHANNEL_SNAPSHOT_MODEL`、`CHANNEL_SNAPSHOT_API_KEY` 和 `CHANNEL_SNAPSHOT_PROTOCOL`。不要把这些值写入仓库、PR 或报告。

环境准备好后，一键命令固定为：

```powershell
python scripts/channel_snapshot.py
```

命令把 JSON 快照写到系统临时目录下权限受限的唯一运行目录，并打印实际路径。可用 `CHANNEL_SNAPSHOT_OUTPUT` 指定其他仓库外路径。快照只保留渠道别名、稳定标识、协议、移除用户信息/路径/查询参数/片段的主机信息、模型数量、UTC 提取时间、探测状态、固定错误摘要与不含凭据的配置指纹。它不保存 API Key/Token/Cookie、认证头、完整 URL 查询参数、客户信息、原始请求/响应或原始错误载荷。上游未通过时仍会写出脱敏的“待确认”快照，命令以状态码 `2` 结束。

容器部署：

```powershell
Copy-Item .env.example .env
docker compose config --quiet
docker compose up -d --build
```

`compose.yml` 把测试平台限制为 0.5 vCPU、512 MiB、2 个普通 Worker，使用非 root 用户、只读根文件系统、无 Linux capabilities、健康检查和自动重启。中转站不包含在本 Compose 中，应作为另一容器部署；二者只通过明确的只读 HTTPS 接口通信。

## GitHub 安全发布

运行平台不会自行改代码。权威项目和公开发布工作副本分离；首次发布先克隆目标仓库，再同步并检查将要上传的内容：

```powershell
git clone https://github.com/yl0711-coder/newapi-evaluator.git github-publish
python scripts/publish_github.py --sync-only
```

发布脚本使用 `repo-allowlist.txt` 把功能源码与明确题库同步到 `github-publish`，同步前后都检查文件类型和敏感内容，并清除发布工作副本中的历史残留。当前唯一允许以 JSON 发布的题库是 `app/hard_items.json`；渠道配置、数据库、凭据、日志、备份、运行证据、导出和其他运行数据均不上传。

首次同步后通过 GitHub Desktop 创建 `main` 的首个 Commit 并推送。后续创建功能分支时运行：

```powershell
python scripts/publish_github.py --summary "本次功能摘要"
```

脚本只允许推送到 `yl0711-coder/newapi-evaluator`，执行轻量本地检查后推送独立功能分支并输出 PR 地址。GitHub CI 会在 PR 和 `main` 更新时执行完整回归与同一安全扫描。

PR 合并到 `main` 后，推送任意 Git Tag 会自动构建并发布同名 GHCR 镜像：

```powershell
git tag v1.0.0
git push origin v1.0.0
```

镜像地址为 `ghcr.io/yl0711-coder/newapi-evaluator:v1.0.0`。工作流只发布该 Tag，不自动更新 `latest`；Docker 构建上下文会再次排除所有运行数据和秘密。

CI 再次执行同一白名单和秘密扫描，拒绝数据库、日志、备份、Key、`.env`、高熵字符串和未允许文件。真实渠道 Key 和生产数据不进入 GitHub Actions 或 artifact。

## 验证

```powershell
python run_selftests.py
```

自测使用 `selftest.db`、`metrics-selftest.db` 和专用 selftest 备份目录，执行前后只清理这些明确命名的测试文件，不接触正式数据库。套件覆盖题库、协议、规则、专项、生命周期、工作台、认证/CSRF/SSRF、洞察、异常归因、本地执行器、任务租约/死信、备份恢复、飞书 Outbox、定时调度、API 端到端和历史兼容。

## 主要页面

- `/admission.html`：五步极简准入。
- `/workspace.html`：模型、平台组、标杆、别名和生命周期。
- `/insights.html`：生产健康、排行、缺口和效果复盘。
- `/incidents.html`：监测告警、证据与归因。
- `/load.html`：本地执行器配对和压力任务。
- `/launches.html`：上线核验与飞书同步。
- `/history.html`：任务、报告、负责人、标签和审查。
- `/admin.html`：匿名用途绑定、出站策略、备份、系统告警和审计。
