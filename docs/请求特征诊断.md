# 请求特征诊断

## 用途与证据边界

将站 A 日志中的 Token、耗时、HTTP 状态和流式标记作为案例，在站 B 使用合成文本做小样本对照。逐轮交错执行基准、输入减半、输出上限减半、切换流式，观察哪些条件下出现慢、断流、拒绝或错误。

原请求正文、模型参数、原网络、历史负载未知，无法复现原内容，也无法仅凭一次站 B 的结果判断故障归属。案例的失败输出 Token 不等于原输出上限。耗时口径未知时不计算历史比值；没有历史时间序列时不推导并发。

## 启动子项目

在仓库根使用已安装 `requirements.txt` 的 Python 3.13 环境：

```bash
python -B scripts/start_diagnosis.py --data-dir /absolute/external/diagnosis-data --port 8096
```

打开 `http://127.0.0.1:8096/diagnosis/`。启动器要求数据在源码目录之外；默认本机监听。`run.py --app all` 也包含该工具，部署时设置仓库外的 `PLATFORM_DATA_DIR`。

公共渠道资料保存在传入数据根，诊断库在其 `diagnosis/` 下。不要把开发验证目录指向业务目录。案例和运行记录可在页面删除；删除案例保留已有报告快照，清除历史特征需同时删除对应运行记录。

部署工作台时沿用现有数据目录和配套密钥，即可使用已有公共渠道，无需执行数据库升级命令或修改现有表结构。首次启动诊断会自动创建独立的 `diagnosis/diagnosis.db`；已有诊断案例和历史记录继续读取，运行过程按原规则保存指标和归档中断状态。

## 操作流程

1. 录入指标或导入 JSON / JSONL。每批 1–50 条、最大 256 KiB；拒绝正文、凭据等额外字段。案例最多 1000 条，运行最多 500 条。
2. 选择案例、协议和目标；明确填写合成输入估算、输出上限、对照组和重复次数。只知道总 Token 时保持历史分项未知，页面中的分项为操作者确认的测试值。
3. 预览请求数量、预算、目标和局限。预览 5 分钟有效，修改条件后重新预览。
4. 开始运行并查看结果。最多 20 次串行请求，每次最多 180 秒，整次最多 1800 秒；同一数据目录只允许一个实例，一个实例同时只执行一项诊断。
5. 下载 JSON 完整指标及计划快照，或 Markdown 摘要。该工具不保存生成的请求文本或上游响应正文。

示例为合成指标，支持数组、`{"cases": [...]}` 或逐行对象：

```json
{"total_tokens":1500,"latency_ms":8000,"latency_kind":"total","status_code":200,"stream":true}
```

Token 字段至少一项；`stream` 必填。可选 `input_tokens`、`output_tokens`、`total_tokens`、`latency_ms`、`latency_kind`、`status_code`。未知用 null 或不提供；`latency_kind` 为 `unknown`、`total` 或 `first_content`。若三个 Token 字段均提供，必须相加一致。

## Mock 与真实渠道

默认本地 Mock，提供正常、大输入限流、流提前结束、首段延迟、缺少 usage 场景。Mock 使用本次进程专属的 loopback HTTP 服务，经过实际 HTTP/SSE 测量链路；usage 为夹具值，不是模型实测。

真实公共渠道可直接选择，无需额外部署开关；渠道列表来自当前工作台数据目录中的公共渠道库，仅提供已启用渠道。操作者明确选择模型名称和协议，在每次计划预览后勾选确认，再点击开始才会发送请求。诊断仅保存渠道 ID、版本、安全别名及目标指纹，发送前解析凭据并核对版本。配置变化拒用旧计划，运行中后续请求停止。连接使用工作台统一出站防护、无重试、不跟随重定向；凭据不会进入诊断报告。

协议为 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 的文本输入与文本输出子集。模型是否支持相应字段需真实环境另行验证；当前不宣称工具调用、多模态、内容审查和模型推理过程的复现能力。

## 指标与恢复

- 输入按 ASCII 字符数 / 4 估算，不含协议封装开销，不保证精确 Token 配平。输出字段是生成上限，不保证生成长度。估算预算不构成实际费用硬上限。
- 实际输入/输出/reasoning Token 只来自响应 usage，缺失为 null。Anthropic 累计 usage 覆盖更新，不累计相加。
- 首段耗时从发出请求至首个可见文本，排除 ping 和角色事件。非流式首段口径为完整正文接收与解析完成。文本空闲时限不因心跳重置。
- HTTP 200、协议终止和结束原因分别记录。达到输出上限单列为 `output_limit`（包括推理消耗额度而未生成可见文本）；`request_ok` 包含该状态，`completed` 只计正常结束。流 EOF 缺少协议结束标记为不完整。
- 每组中位数只使用 `request_ok` 样本，同时保留失败的逐条耗时；小样本不报告 p95 或故障归属结论。
- 发送前写入运行状态，结束后写入指标。取消停止后续请求并关闭当前连接；上游可能已接收或继续计费。进程重启将未确认的请求标 `unknown`，尚未发送项标 `not_sent`，从不自动重发。
- 无自动重试；401/403 后停止余下请求。达到运行时限保留已完成/部分指标。

## 一键只读核对

```bash
python -B -m features.diagnosis.inspect --data-dir /absolute/external/diagnosis-data
python -B -m features.diagnosis.inspect --data-dir /absolute/external/diagnosis-data --channel-id 1 --protocol responses --model explicit-model
```

不初始化数据库、不解密凭据、不发送请求；只输出安全别名、协议/模型、版本、遮蔽主机、指纹和核对时间。第二条要求已存在公共渠道记录。

## 验证与维护

本模块的案例与诊断编排归工作台维护；`relay_lab` 五模式及共享极限业务不变。统一鉴权、渠道和出站防护由 `shared` 提供。该模块没有迁移既有产品报告。

完整检查入口及依赖见 [请求特征诊断测试清单](请求特征诊断测试清单.md)。真实目标可用性、真实 Token 误差、长时负载与故障归属不在本地 Mock 验收结论中。
