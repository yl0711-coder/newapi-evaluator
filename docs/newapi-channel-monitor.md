# New API 渠道自动监控

工作台 `/channel-monitor/` 为 `v1.0.0-rc.26` 提供半小时直测及单渠道启停。默认暂停；保存管理连接和映射不会发模型请求。管理令牌与公共渠道模型 Key 分开加密保存。管理连接需要 ChannelRead、ChannelOperate 权限，模型调用令牌不能替代管理令牌。

每道题最多发送五次（首次加四次重试），重试前分别等待2、4、8、16秒。断联、超时、空响应及上游 HTTP 错误可重试；五次均记录为已确认请求故障才申请停用。程序中断、出口拒绝、取消、配置漂移、未知结果、评分格式无效均不能凑成五次失败。有效回答立即停止重试，不因答错继续刷题。

每轮先测已有 hard-3 糖果题。糖果请求有效完成后，无论答对、答错或答案格式无法判分，均执行三个固定 ModelTrace 探针；三个探针共同形成该轮的一次 MT 结论。连续两个相邻半小时定时轮次均糖果答错且 MT 明确不匹配，或连续三个相邻半小时定时轮次均糖果答对但 MT 明确不匹配，才申请停用。两条路径独立计数；答对与答错路径切换从1开始，MT匹配、无法判定、漏轮及手动测试均中断连续计数。糖果格式无法判分不进入任何质量计数。逐条质量停用前重新读取完整库存，检查该渠道所有模型及分组，停用后每个组合须至少四条已启用渠道；不足时保留渠道并在页面告警。API 指纹尚未校准，结果是闭集行为信号，不能认证真实模型权重。

所有自动停用共用四条底线，包括请求故障。每轮先收齐全部观测，再处理动作；先恢复本轮合格的自有停用渠道并确认回读，然后逐条重新读取完整 New API 库存，核对目标所有分组×模型。候补只覆盖部分组合仍不能停用；候补启用未确认、取消或期间漂移会阻止本轮后续停用。没有合格补位时保留原渠道并在页面告警，不能同时承诺停用故障渠道和保留四条。四条是后台启用数量，不保证四条均能正常响应。

请求故障候选若在动作阶段仍会跌破四条，先等待60秒，再用独立 `candy-recheck` 许可实际测试一次连通性。有有效模型响应则保留，答案正确性不进入质量计数；仍故障也必须通过四条门闩，否则保留告警。该连通性复测只发一次，不补测MT、不扩大原窗口，也不再次累计本轮质量计数。熔断或补位未确认时已暂停停用，不追加这次复测。

停用仅修改 New API 状态，不停用 Eval 公共渠道。故障和质量停用的普通恢复及补位共用条件：本轮糖果答对、三个有效MT探针共同明确匹配，且在本轮完整飞书正向上线白名单中；一轮通过即可。白名单通过“公共渠道→从飞书同步渠道”既有配置和读取器获取，不使用机器人Webhook；先完成一次手动同步。候选须由同一source_id/record_id绑定到Registry，配置version、成功同步generation和连接fingerprint一致，Registry仍启用且online；缺行、下线、空Key、坏行、重复连接、换配置未同步或读取失败均不能恢复。读名单不导入或重新启用Registry；缺失与失败也不能引发正在使用渠道的批量停用。每轮存在未锁定的自有停用渠道时只读获取一次完整名单，不复用旧轮次。每次自有停用直测许可及最终启用事务再次校验名单与本地身份。

只恢复本监控有确认写入和回读记录、当前仍为状态2的渠道；当前已启用则解除所有权，不重复启用。人工锁定、接管、外部停用、配置变化或未知写入均不能作为候补。取消、窗口到期、出口策略拒绝及配置漂移中止本轮；暂停停止后续发送，已许可的管理写入可能执行，须查看账本。

同轮至少两个不同New API渠道耗尽请求机会即持久打开熔断，在任何禁用写入前暂停全部自动停用，检测和合格恢复继续。后续scheduled轮次至少两个当前未锁定映射，且所有当前未锁定映射均完成糖果正确和MT匹配，最终复验当前映射全集、revision、Registry连接、管理配置与状态后才自动解除。未知、漏测、外部停用、途中解锁或配置漂移不能解除；manual轮不能自动解除。人工解除须先暂停计划、核对故障原因并确认，revision冲突拒绝，解除后计划仍暂停。熔断重启保留，解锁及计划重启不隐式清除。

每映射每轮最多4道质量题加1次连通性复测，最多21次物理请求。某个 MT 探针耗尽五次故障后结束本轮质量检测，后续探针记为 `not_run`，保留三个探针的计划分母；未知、漏测或物理重试不能凑成质量轮次。检测合同为 `newapi-channel-monitor-v3`，包括统一底线、白名单恢复、熔断和重试退避；旧合同映射拒绝继续发送，需暂停并重新绑定。启用计划须分别确认模型请求、管理动作和所需的定时飞书读取，保存和开页均零出站。

配置时精确指定 New API 渠道 ID、Eval 公共渠道 ID、模型和协议，不按名称猜测。当前支持单密钥、无额外参数/请求头转换的 type=1 OpenAI 兼容渠道；地址、模型映射及连接指纹须一致。rc.26 普通渠道读取不提供密钥，操作人须核对两边使用同一把上游 Key；后台换 Key 后须暂停并重新绑定。rc.26 状态接口没有 CAS 或独立自动化所有者标识；自动操作在本实例内串行执行，外部同时修改库存无法获得跨系统事务保证。人工维护前使用页面锁定或暂停。

管理读取等待结束后重新读取公共渠道状态与连接；模型发送及管理动作的最终许可，在同一 Registry 写事务内复核启用状态、连接指纹与精确模型映射。等待期间停用渠道、换 Key 或改变映射会阻止后续发送和启停，不记为渠道故障，也不认领停用所有权。

适配依据为官方 rc.26 的 [渠道模型与状态写入](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.26/model/channel.go)、[管理控制器](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.26/controller/channel.go) 及 [渠道设置](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.26/relaykit/dto/channel_settings.go)。仅允许已核对的空值和默认设置；组织头、代理、系统提示、透传、参数/请求头/状态码转换及未知设置拒绝绑定。启停自身更新的 `other_info.status_reason/status_time` 不计入连接指纹，其他配置仍参与漂移检查。动作账本冻结实例指纹、渠道 ID、模型协议及检测条件，并保存触发结果、连续次数和门槛；恢复、移除映射或更换管理连接不会改写历史依据。

排期复用 Eval 现有稳定性调度器和数据目录锁。保存启用计划后从下一个半小时时隙开始，按开始到开始计时；原时隙 1100 秒窗口不延长，错过直接跳过，不补测、不创建漏轮。手动轮成功建立时即原子清空质量连续计数，中途取消、退出、重启或评测前拒绝均不保留旧计数；未能建立的手动轮不改变计数。立即测试不改变半小时锚点。所有模型请求复用共享传输与发送容量，长耗时可能使部分目标在本轮未测，不能将其判为故障。

复用依据是用户指定的「建立每20分钟渠道定时测试计划 (2)」及其 `定时测试-20261010` 独立执行器：末行整数判分、独立尝试身份、固定开始计时、原窗口截止、完整 usage 和中断保留。历史运行配置、密钥、账本、冻结 runtime 和原生 heartbeat 保持独立；新模块没有导入或改写这些运行文件。历史脚本的 401/403/404 提前停止和一次指纹重试不作为本模块五次故障门槛。

只读检查：`python -B -m features.channel_monitor inspect-config`。只输出规则与配置指纹，不打开数据库、不读凭据、不联网。

开发与独立验收使用 `scripts/verify_integrity.py` 注册清单，新增 Python 状态机/管理协议回归、只读检查和浏览器交互。全部使用合成输入与本地 Mock；不证明真实管理权限、真实模型身份或生产调度已经启用。
