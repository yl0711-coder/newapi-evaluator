# 请求特征诊断候选测试清单 v1

适用：当前工作台功能分支的代码交付；依据正式规则 v1.0。启动器与挂载变化触发容器验证；页面变化触发两个浏览器组。合成夹具在 `tests/test_diagnosis*.py` 与 `scripts/diagnosis_ui.cjs`；不读取业务日志、渠道库或通知配置。

使用 Python 3.13、requirements.txt、Node 24、Playwright 及 Chromium（可用 `PLAYWRIGHT_CHANNEL=msedge`）、Docker。环境、venv、TMPDIR 和结果全部位于仓库外。可指定 `PLAYWRIGHT_MODULE` 与 `PYTHON_EXECUTABLE`（统一入口自动设置后者）。未配置类型/格式工具，如实标记，不冒充类型检查。

```bash
python -B scripts/verify_diagnosis.py --output /absolute/external/new-verification
```

独立验收使用干净 detached SHA、独立安装的 Python 环境与新数据，加 `--sha <40位SHA>`。此时还执行既有 `scripts/acceptance.py` 的配置核对、持续负载与混合突发 CLI 等 10 组核对。不会执行 Git 远端操作或真实上游请求。

| suite_id | 入口 | 验证与收集规则 | 单组上限 |
| --- | --- | --- | ---: |
| workbench-python | scripts/test_all.py | 全部三引擎自测及 tests 下 unittest；固定基线 34/41 个 unittest、22 项稳定性检查，加动态发现用例数；拒绝跳过/零收集 | 900s |
| workbench-web | node scripts/test_web.js | 既有实时推子、表单和状态契约 | 120s |
| workbench-security | scripts/repo_security_scan.py . | 全部 tracked/untracked 非忽略源码；秘密与运行数据、Python AST | 120s |
| syntax | scripts/diagnosis_syntax.py | 全部 Python、JS/CJS/MJS、HTML 内联脚本，拒绝零收集 | 300s |
| workbench-e2e | scripts/e2e.py --output 分配目录 | 五模式实际本地 Mock HTTP/SSE 和报告 | 600s |
| workbench-browser | node scripts/ui_smoke.cjs | 公共渠道、准入、非流式、稳定性、极限的既有宽窄屏操作与导出 | 600s |
| diagnosis-browser | node scripts/diagnosis_ui.cjs | 新工具独立启动、导入、计划失效、对照、历史、导出、删除、宽窄屏 | 300s |

| legacy-acceptance | scripts/acceptance.py --sha 候选 --output 分配目录 | 仅独立验收阶段；原有完整 10 组、持续负载与混合突发及版本一致性 | 1200s |

新诊断的领域/API/传输测试已按 unittest 默认 `test*.py` 发现接入 `workbench-python`，包含三协议、两响应模式、正常/拒绝/错误/缺失结束、首段/空闲/总超时、取消、版本变更、预算、幂等、防止中断重发、未知 Token、不落正文/密钥、出站防护和只读 CLI。执行器自身针对失败、缺失收集、跳过和假成功输出有回归。

统一入口总预算 3600 秒，每组执行时限受剩余总预算限制；超时终止本组专属进程组，记录 incomplete。逐组记录命令、退出码、用时、执行/失败/跳过数量（非框架失败无法确定失败数时 null），状态及日志；未执行保留 not_run。收集数、框架结果和退出码共同判断。Web 契约与既有浏览器按一个集成场景登记，其内部断言不伪称独立用例。

失败尝试保留原目录；修复后使用新目录重验。日志仅为本地合成数据；不能把该执行器指向业务服务。`verification.json` 记录完整 SHA、全部源码指纹、环境和逐组证据。实际环境依赖指纹和审查信息在交接证据中补齐。

范围核对：`scripts/acceptance.py` 的补充项在独立阶段执行；其已覆盖的聚焦、全量、安全、JS/E2E 与统一入口存在重复，保留以验证既有验收契约。真实压力/长期实测在本任务未授权且不适用。实验室无源码修改，不重复建立跨项目全量阶段。
