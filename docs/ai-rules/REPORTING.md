# 产品报告兼容规范

状态：正式规则 v1.0。用户已授权启用；适用范围与操作权限见 CODING.md。

## P1 保留现有行为

维护现有报告的展示内容、版本区别、历史读取、保存和下载行为。AI 不得因共用规范中的“只保留指标”或“禁止正文”删除本来用于人工判断的题目、回答或技术证据，也不得据此把没有的正文保存功能扩展到其他模块。

改动报告时先核对当前实现、调用方与有效需求，再说明影响；本基线不冻结未来获授权的功能迭代。发现文档和实际行为不一致时，记录差异，不自行删功能来迎合旧文档。

## P2 当前工作台基线

以下由 2026-09-14 的 README 和相关代码只读核对得到，不是本轮浏览器实测或脱敏安全认证。核对版本、文件指纹和已有修改见 `reporting-baseline.json`（随规则版本保存的源码指纹）。

| 模块 | 需要保留的报告能力 | 保存与下载边界 |
| --- | --- | --- |
| 准入测试 | 运行结论、逐题摘要、题目与双端回答、折叠技术证据；人工阅读回答判断能力 | 后端保存最近 30 条；保留历史查看、普通版 HTML、技术版 HTML、技术版 JSON 及现有历史报告下载；普通版与技术版不强求字段完全一致 |
| 非流式回答测试 | 题目、答案、上游返回的可见推理、usage、结束/截断信息、现有脱敏原始响应展示 | 保留本轮页面展示与 JSON 下载；页面刷新清空，不新增后端历史存储 |
| 定时稳定性测试 | 现有速度、稳定性、基线与异常分类报告，以及已配置的通知内容 | 沿用当前历史与通知机制；默认已完成且通知处理完毕的报告和明细保留 5 天，尊重已有配置，不在本轮调整 |
| 极限测试 | 模式、负载、时间线、请求级指标、汇总和结论边界 | 保留现有请求级 JSONL、汇总及报告；“原始结果”指请求级指标，不新增 Prompt 或回答正文保存 |

本表只概括已核对的模块。其他项目或未合入的开发线须依据各自实际功能补充基线，不直接套用工作台的全部能力。

代码依据（工作台仓库相对路径）：`features/admission/web/app.js`、`features/admission/reporting.py`、`features/admission/storage.py`、`features/reasoning/web/index.html`、`features/reasoning/main.py`、`features/stability/app/storage.py`、`relay_lab/report.py`、`relay_lab/model.py`。实验室及旧分支按实际存在模块核对。

## P3 内容与输出渠道

产品已有的题目、回答、可见推理和技术响应展示按 P2 保留，沿用其脱敏与访问控制要求。API Key、凭据、访问令牌、Cookie、完整敏感 URL/查询参数及可识别客户信息不得因“保持现状”成为允许输出的内容；若发现泄漏，按 REVIEW.md 记录和处理，不把缺陷当作产品契约。

产品报告允许的内容不自动成为运行日志、Git、开发验收报告、AI 聊天或新增外发渠道的允许内容。开发与验收证据使用合成夹具、脱敏指标和定位摘要；不复制真实报告正文。既有外部通知维持自身已授权的内容范围，不因为产品可下载报告就自动发送整份报告。

现有业务模块使用的测试题不因本报告规则被删除。允许为自动化回归独立编写合成题目、答案、响应和预期值，并纳入版本管理：内容无真实业务来源、不含敏感信息，放在项目登记的测试或夹具位置，接受测试清单和安全扫描的检查。客户真实对话、实际运行请求和模型回答不能靠改名、截取或局部脱敏转成这种合成夹具；不得借测试例外复制真实报告或绕过数据边界。

## P4 修改时的验证

对受影响模块验证页面展示、历史读取和各类导出的各自契约；字段、统计口径与同一运行对应，普通版和技术版允许按既有设计展示不同内容。使用合成内容验证转义和脱敏；保留本来需要展示的回答与证据，确保凭据不会混入输出。

按 TESTING.md 的触发条件执行报告相关回归、全量测试与浏览器验证。未运行的检查如实登记，不能用代码阅读代替功能测试通过。
