# 开发与独立验收交接

状态：正式规则 v1.0。用户已授权启用；适用范围与操作权限见 CODING.md。

## H1 角色与交接方式

开发方负责实现、自查、测试和获授权范围内的修复；独立方依据 REVIEW.md 审查并按 TESTING.md 独立验收，不代改业务代码。独立验收可以在同一设备的隔离环境和独立任务上下文完成，不要求购置第二台机器；正式版本、环境和数据隔离仍按 T5/T7。

本地交接用候选提交与外置证据目录。任务已采用并授权 GitHub 协作时，使用其指定分支、提交和 PR；两种方式使用同一份交接内容。继续任务优先恢复正确的已有 worktree，不因模板而重新 clone 或创建重复目录。新任务的分支基线按本项目有效规则核对，不改写已有功能分支来强行追随其他项目的 main。

`yl0711-coder/newapi-evaluator` 的交接须标明仓库身份、适用规范入口及版本。正式落地时将根级 AGENTS.md 与其引用的共用规范纳入仓库版本管理，使用仓库内可解析的引用，并验证实际加载；不能仅依赖某台电脑桌面的父目录。旧提交或只读验收副本没有规范入口时，从明确指定的规范版本读取并记录来源，不为补入指令文件而改动待验收提交。将规则纳入仓库的改动本身仍按 G6 分支开发、验证与合并许可执行。

```text
目标与验收条件：
仓库身份 / 适用规范入口与版本：
项目 / 工作目录 / 角色（实验室来源或工作台集成等）：
基线版本 / 待验收完整 SHA：
任务范围及已有改动边界：
变更与兼容影响（接口、配置、数据、报告）：
复现与环境准备入口：
一键只读检查命令及脱敏输出契约：
完整测试入口与清单版本：
已执行检查、逐组状态及外置证据路径：
未执行项、已知问题及原因：
风险与恢复方式（仅写本次实际适用内容）：
若申请合并：候选版本 / 目标分支及基线 / 完整改动与验证结果：
若使用 PR：链接 / 编号 / 分支 / 当前 head SHA：
```

渠道、连接解析、探测、评测等相关变更应给出该候选版本中受版本控制的脚本或 CLI，一条命令完成只读配置/渠道检查，默认输出稳定标识或安全别名、协议、脱敏主机、模型信息、配置指纹及时间等必要字段。环境准备可以有单独入口，正式检查不要求验收方猜测或手工拼接业务步骤。

命令必须能在指定目录与环境运行；示例占位符、其他项目的同名脚本或不存在的入口不能算已交付。检查不自动发真实请求、创建计划、发送通知或改上游配置，凭据从已授权的仓库外安全位置注入。与该检查确实无关的纯文档等任务写清不适用原因；相关任务缺少入口、执行失败或脱敏不合格时，按 T6 记录，不能用“不适用”掩盖。

一键检查只提供可复核的配置证据，不替代功能测试、全量测试和独立审查；产品报告内容仍由 REPORTING.md 决定。

## H3 独立验收记录

```text
项目 / 阶段 / 交接任务（若有 PR 则附链接）：
仓库身份 / 规范加载来源：
实际完整 SHA / 规则与测试清单版本：
验收前后版本核对 / 工作区状态：
隔离环境与新数据目录 / 环境指纹：
只读检查命令、状态及脱敏摘要：
实际测试命令 / 退出码 / 用例与跳过数量 / 逐组结果：
审查范围 / 问题 ID / 脱敏复现证据：
未审、未跑、不适用和受限范围：
质量状态 / 面向使用者的结论：
交付接受状态 / 若有 T6 例外：问题 ID、版本、阶段范围、影响、指示证据及后续处理：
证据目录 / 已修复问题的复核记录：
```

状态以 T6 为准：整体 `passed` 对应“通过”，`failed` 对应“失败”，`incomplete` 对应“待确认（未完成）”。`not_applicable` 只描述有依据的不适用项，不冒充整体通过；失败不要求每次都可稳定复现，确定的断言或边界失败仍保留失败证据。

用户明确接受历史问题例外时，按 T6 保留 failed/incomplete 的质量状态，单独记录交付接受状态；不得将其映射为“通过”，也不能替代阶段推进、合并或发布的明确授权。

问题绑定实际版本、位置、触发条件、影响和预期结果，开发方据此修复；新版本按 R6 复核与测试。发出结论前按 T7 再次核对候选版本；发生变化时保留旧报告的历史身份。

## H4 已授权的 PR 与发布场景

向目标交付分支的合并按 G6 执行：先完成候选结果、测试和独立审查，再向用户提交该次合并的具体内容，获得明确允许后才写入目标分支。开发与验收通过但尚未获准合并时，记录“开发与验收已完成，待用户允许合并”；不把等待许可说成测试失败，也不宣称已合并。

若使用 PR，描述以 H2 为内容来源，验收记录以 H3 为内容来源，避免模板遗漏 SHA、一键命令或未执行项。默认保持 Draft；测试与审查通过不自行转 Ready 或发布。已经明确允许的同一次合并按其具体范围执行，不重复请求同一许可；对外发送评论或报告须有对应授权。

实验室子集采用 T8 的两阶段流程，分别关联实验室来源 SHA 与工作台候选集成 SHA。准备隔离候选分支不等于已获准合入目标交付分支；合并许可也不扩展到其他目标分支、远端推送或镜像发布。CI 触发、候选版本和构建产物对应关系按 T9 核对。
