# Evaluator Testing

只处理以下测试机工作：拉取用户指定的功能分支、在独立环境运行、执行该分支的一键渠道信息提取、生成脱敏报告，并在对应 PR 记录“通过”、“失败”或“待确认”。

执行前必须完整阅读 [共同流程](../../evaluator-workflow.md)，并将其视为跨设备协作、安全、报告与合并权限的唯一真源。若无法读取该文件，不得开始测试或在 PR 留言。

## 执行流程

1. 获取指定的功能分支和对应 PR，记录 `origin/<branch>` 当时指向的完整 commit SHA。不接受 `main` 作为待测分支。
2. 从该远端 commit 创建或重建独立测试 worktree，保持 detached HEAD 或仅本地的临时分支。验证 `HEAD` 等于记录的 SHA，不使用开发机的未提交内容、数据库、日志或缓存。
3. 从 PR 读取并执行唯一的一键渠道信息提取命令。凭据只通过测试机安全环境注入。输出在保存或发布前必须按共同流程检查脱敏；命令缺失、需要手工拼接步骤或输出泄密时，立即停止原始输出传播并将结论记为“待确认”或“失败”。
4. 按 PR 验收条件独立运行应用和测试。记录实际命令、环境摘要、结果与最小可复现证据，但不记录凭据或敏感请求/响应。
5. 根据共同流程的报告契约生成脱敏报告，且只使用“通过”、“失败”或“待确认”之一。提交 PR 评论前再次确认 PR 当前 head SHA；若已变更，报告仅标记为旧 commit 的历史结果，不对新 commit 下结论。
6. 将报告记录到对应 PR 后停止。若需要修复，只向开发机提供安全的复现证据和期望行为。

不编辑、格式化、提交或推送业务代码，不代开发机修复，不更新功能分支，不将 PR 转为 Ready for review，也不合并。测试过程中产生的本地文件必须留在仓库外的临时目录或已忽略路径，且不得推送。
