# newapi-evaluator 开发与测试协作流程

本文件是开发机、测试机以及项目级 Codex skill 的唯一共同流程真源。两端只通过 GitHub 分支、commit 和 PR 同步；与本文件冲突的临时说明不得扩大权限。

## 不可变规则

- 任何设备都不得直接修改、提交、推送或合并 `main`；功能分支必须从最新 `origin/main` 创建。
- 测试机只读取指定功能分支并记录测试结果，不得修改、提交或推送业务代码。发现问题时由开发机修复并推送新 commit，测试机再次验证。
- 每个功能沙盒都必须在 PR 描述中给出一条可直接执行的“一键提取渠道信息”命令。命令必须来自该 commit 内受版本控制的脚本或 CLI，完成可复现的渠道信息提取并输出脱敏结果；不得要求测试人手工拼接多条命令。命令缺失、无法执行或输出不安全时，测试结论只能是“待确认”或“失败”。
- 测试报告必须关联实际验证的完整 commit SHA。分支名不能代替 SHA；分支更新后，旧报告不能作为新 commit 的通过证据。
- 不得在 Git、PR、Issue、报告、日志或聊天中提交或粘贴 API Key、凭据、访问令牌、Cookie、完整敏感 URL/查询参数、完整上游请求或响应。只允许最小必要的脱敏摘要；若无法确认已脱敏，就不上传。
- 只有项目所有者明确确认后才能合并。测试通过、审批通过、CI 通过或用户要求“完成”都不等于合并授权。默认保持 Draft PR，禁止自动合并。

## 功能分支与沙盒契约

1. 开发机先获取最新 `origin/main`，再以 `feature/<slug>`、`fix/<slug>` 或用户指定的非 `main` 分支名创建独立 Git worktree。一个 worktree 只服务一个功能分支。
2. 开发机在功能 worktree 内开发、运行与变更风险匹配的测试，确认 diff 只包含本次任务。提交前必须运行 `python run_selftests.py`、前端 JavaScript 语法检查，以及 `python scripts/repo_security_scan.py .`；若环境或范围使某项不适用，在 PR 中说明未运行项与原因。
3. 开发机提交并推送功能分支，创建 Draft PR。PR 必须说明变更、风险/回滚、测试结果、一键渠道信息提取命令，以及等待测试的 commit SHA。
4. 测试机在自己的独立 worktree 中 fetch 指定分支，将待测对象固定到 `origin/<branch>` 当时的 commit SHA，不重用开发机的运行状态或未追踪文件。
5. 测试机先运行 PR 指定的一键渠道信息提取命令，检查输出脱敏，再独立执行复现、自测与验收。凭据仅通过本机安全环境注入，不得写入工作树或报告。
6. 测试机把脱敏报告记录到对应 PR。失败或待确认时，开发机根据报告修复、推送新 commit，然后回到第 4 步。
7. 最新 commit 获得“通过”结论后，PR 仍保持未合并，等待项目所有者明确确认。

## 渠道信息与脱敏报告契约

一键命令的输出应仅包含识别和验收所需的字段，例如渠道的稳定标识或脱敏别名、协议、脱敏后的主机信息、模型列表/数量、配置指纹与提取时间。以下内容必须删除或不可逆地遮罩：Key/令牌、鉴权头、Cookie、完整查询参数、客户身份、Prompt、完整请求/响应正文及原始错误载荷。

PR 测试记录的结论只能是：

- `通过`：所有必需验收均通过，且报告对应 PR 的当前 commit。
- `失败`：已获得可复现的失败证据。
- `待确认`：因需求、环境、权限、安全脱敏或一键命令问题无法得出可靠结论。

每份报告必须包含：PR 链接/编号、分支、完整 commit SHA、测试环境摘要、一键提取命令及脱敏渠道摘要、实际执行的测试与结果、失败复现步骤或待确认项，以及最终结论。报告不得附带未脱敏的原始输出。

## 停止条件

- 开发机：只在功能分支上推送变更，并根据已关联 commit 的 PR 测试反馈修复；遇到需要合并、改动 `main` 或扩大业务范围时停止并等待明确指示。
- 测试机：写入 PR 报告后停止；不代修、不推送代码、不合并。若发现任何可能的敏感信息泄露，停止上传原始材料，仅记录脱敏后的安全告警。
