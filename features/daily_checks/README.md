# 已上线渠道每日检测

工作台及独立稳定性模式的 `/daily-checks/` 页面提供每日检测配置、预算预览、启用/暂停、飞书 Webhook、批次取消、送达状态和 JSON/Markdown 导出。复用稳定性调度器与同一数据目录锁，不新建后台进程。原有 MT/Nerfed 和半小时 Token 计划保持各自启用状态；需要避免重复测试时，由使用者暂停原计划。

## 设置与时间

表格维护后，先在公共渠道页点击手动同步。每日检测只读最近一次同步后的 Registry，不自动读取飞书表格或 New API 后台。GPT/codex 和 Claude 分别选择确切模型 ID、已登记协议及可信参照。请求使用现有精确模型映射；双端必须同模型、同协议。修改可信绑定会使引用旧 revision 的检测停止，需重新保存计划。

| 开始检测 | 汇总并推送 |
| --- | --- |
| 09:30 | 10:30 |
| 13:00 | 14:00 |
| 14:30 | 15:30 |
| 17:00 | 18:00 |

时间固定为 `Asia/Shanghai`。保存后从下一个开始时刻运行，不追赶保存前的时刻。提前结束仍等原报告时刻；到时取消余下等待，保存已有结果并推送。服务错过当日已生效窗口时生成缺测报告、零补发；宕机可能延迟推送，不能保证一小时内覆盖全部渠道或准点送达。

每轮冻结全部 `status=online` 渠道作为分母。仅启用且凭据可用的已配置家族实际发送；未识别家族、停用、缺 Key、缺模型或映射无效均列出原因。`codex/openai/gpt*` 属于 GPT，`claude*/anthropic` 属于 Claude；多家族展开多行，同渠道名称放在一起。可信参照自身仅测 ModelTrace，不做 Token 自对照，报告明确说明。

## 请求、判断与速度

每组合固定 ModelTrace 3 次、输入 Token 双端首次 2 次；首次重大偏差最多再做双端 2 次，共最多 7 次，零重试。参照请求也计入预览预算。ModelTrace 与原完整性请求共用在途上限 1；所有请求共用 probe 在途上限 2。每个候选组合依次执行 MT 与用量；同轮不同方法不混算速度。

ModelTrace 使用已有冻结数字探针、bank 和真实评分。不在 bank 中的模型保留观测、结论“无法判定”；Claude 已知点号 ID 映射到 bank 的连字符身份。普通 API 比较未校准，达到保守排名门槛时只表述行为更接近某模型，不能认证真实权重。

Token 使用现有固定合成长输入及相同请求参数。OpenAI 输入已包含缓存读；Claude 归一未缓存、缓存读与缓存写。重大偏差沿用首次 `>=2x` 且差值 `>=1024` 的判据，首证据不被复核或取消抹掉。小偏差须同冻结条件、同可信 revision、相邻两个指定报告批次确认；漏一轮重新等待确认。缺失、冲突、异常终态或无效参照均“无法判定”。`billing_status=unverified`，不推断账单多扣。

报告记录各方法实际尝试、成功、未测、unknown、错误类别、成功请求响应中位数、首文本中位数及可测的 Token/s。单位分别为 ms 和 Token/s；缺值为 null、少量样本不计算 P95。Token/s 仅完整流式、明确 reasoning=0 且有 reported output 时有效。稳定性仅描述本轮有限请求，不能作为全天可用率。

## 确认、恢复与通知

本模块的 UI 真实请求确认入口为 `PUT /api/daily-checks/plan` 的 `enabled=true, confirm_live=true`，须带当前预览 fingerprint；勾选页面确认等价于本模块的显式 live 确认。新增或变更可信绑定另需 `confirm_trusted=true`。推送另需 `confirm_notify=true` 和有效 Webhook。保存、预览、打开页面、查询及导出零发送，默认暂停；开发与验收仍只使用隔离 Mock。模块不会修改上游配置。

每次最终发送许可复验计划 revision、原截止时间、online/启用状态、连接、映射与可信绑定。同一时刻、渠道及家族使用确定性任务键，confirmed 和 unknown 不重发。MT 中断可在原窗继续尚未许可的项；Token 租约过期恢复保留 unknown，已终结任务不自动重开。暂停或取消停止后续请求，无法保证上游已经停止处理在途请求。

Webhook 在密码框输入、提交即清空，由原稳定性设置加密保存且不回显。仅允许官方 HTTPS v2 群机器人 URL；与原稳定性通知共用该配置。机器人关键词规则需允许报告标题；需要签名校验的机器人当前需更换为可用配置。通知仅外发安全名称、ID、倍率、模型、结论、覆盖和白名单指标，不发送 Key、地址、题目或回答。按照单条请求体 20 KB 上限分片并编号，响应必须明确成功；依据 [飞书官方机器人合同](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

发送中重启或网络失败记 unknown，拒绝响应记 failed，不自动重试；页面“重发未送达片段”须另勾确认，仅重发 failed/unknown/disabled，unknown 可能重复送达。取消提前生成的报告仍等原报告时刻。沿用原保留天数，默认5天，仅删除终态且通知全部送达的报告；未送达报告与请求许可账本保留。

## 验证入口

`python -B scripts/inspect_daily_checks.py` 为一键只读检查：输出四时段、预算合同、指纹及零数据库/凭据/请求/通知声明。新用例 `tests.test_daily_checks` 注册到完整 Python 收集；浏览器 `scripts/daily_checks_ui.cjs` 使用自有回环 HTTP、合成飞书传输，覆盖页面、确认、报告、导出、暂停与390/900/1440布局。完整开发及独立验收使用 [完整性测试清单](../../docs/integrity-testing.md)，Mock 不证明真实模型、账单、机器人授权或全天容量。
