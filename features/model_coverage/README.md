# 常用模型覆盖

公共渠道页面中的子模块：统一常用模型清单、人工获取上游列表、测试接入状态与实测结果、单次验证、批量加入已有定时计划。后端 Python / FastAPI，复用公共渠道凭据和定时调度器。入口 `/channels/`，API `/api/model-coverage`。

## 操作

1. 厂商发布新模型后，添加到常用清单；所有公共渠道同步出现该模型。也可以从某渠道的“其他已发现模型”中添加。
2. 点击“获取模型”或“获取所有渠道模型”，选择 Bearer 或 Anthropic 鉴权并确认。只在这次人工操作中请求上游，不创建定时获取任务。每次获取最长 30 秒、最多 20 页，每页 2 MB、最多 10000 个不同模型，分页仅接受同地址的 Anthropic after_id；不跟随返回 URL 或重定向，不读取环境代理。
3. 如上游采用别名，用“映射”填写实际模型 ID 和测试协议。模型匹配为精确匹配，不根据名称片段猜测等价关系。标准或实际模型 ID 为 gpt-6-astra 时，只接受 Responses；已有错误映射必须先纠正，才能执行单次验证或加入计划。
4. 勾选模型后可执行单次验证，或选择已启用的定时计划、检查新增请求量并确认加入。单次验证执行现有六题一轮，进入观察记录；不关联定时计划、不发送通知。已暂停的目标需要通过加入计划明确恢复，单次验证不会恢复它。加入计划复用已有目标，保留计划其他目标与配置，最多 100 个目标；保存不立即测试。

默认 12 个常用模型：GPT-5.5、GPT-5.6 Luna/Terra/Sol、GPT-6 Astra，以及 Claude Fable 5.1/5、Opus 5/4.8/4.7、Sonnet 5/4.6。目录最多 200 项。新增模型的名称与协议由使用者填写；上游返回名称不构成模型真实性认证。

## 三类状态

| 维度 | 含义 |
| --- | --- |
| 上游提供 | 已列出、未列出、尚未获取、获取失败、连接已变更。获取失败保留上次成功清单与时间；未列出不代表无法调用。成功清单不因时间自动过期。 |
| 定时测试 | 渠道、目标和至少一个关联计划都启用才显示已加入计划。仅建目标为待排期；未建目标为未接入；相关配置停用为已暂停。来自实际目标和计划关系，不保存一份容易漂移的人工标记。 |
| 实测 | 未测试、可用待观察、稳定、不稳定、结果已过期、连接变更待重测。只统计同一公共渠道、实际模型 ID、协议及连接指纹的结果。 |

实测采用最近 7 天内最新 5 个独立完成批次；至少 3 批均满足各自运行快照中的成功率、超时率与断流率阈值才显示稳定，任一批不达标显示不稳定。重复目标的同一运行不重复计批。最近一次测试超过 48 小时显示过期；每天一次的测试可以在第三天积累足够样本。展示批数、成功请求数/全部请求数、最近测试时间与报告入口。稳定性与速度分别展示，速度沿用现有固定/自适应规则；自适应速度基线只引用同一连接与协议的记录，切换协议后重新采样。

地址或密钥变化使历史观测与新连接分离；改名称、备注或倍率不使连接身份变化。新观测在定时报告完成事务中写入，不依赖页面打开；页面每 15 秒读取本地状态，不触发上游获取或测试。每个渠道/实际模型/协议最多保留 30 条不含正文的观测，历史报告仍按原策略保留；报告已清理时不展示失效链接。旧报告继续可读，缺少连接证据的旧报告不自动变成新模块的稳定性证据。

GPT-6 Astra 的定时目标强制 Responses。Responses 测量复用准入 SSE 解析器，流式必须完整 response.completed；缺结束、协议错误、拒答、截断或无正文不会通过。合法失败事件归为“上游处理失败”（upstream_error），格式损坏或结束事件冲突归为“无效响应”（invalid_response），HTTP 5xx 保留原分类。单请求总限时 240 秒；max_output_tokens=4096、reasoning.effort=low、store=false，兼容流式与非流式。缺失用量保持 null，含推理用量或由结束事件补齐正文时不计算正文 Token/s。定时测试全局最多同时 2 个生成请求保持有效。

## 数据与 API

公共 `channels.db` 新增 model_catalog、channel_model_bindings、channel_model_discovery；`stability.db` 新增 model_observations。仅增表，不删除、搬迁或重置旧数据。API Key 仅由服务端解析，观测保存连接 HMAC 与白名单指标，不含 Key、题目、回答或响应正文。

| 接口 | 输入 / 行为 |
| --- | --- |
| GET `/api/model-coverage` | 本地目录、每渠道状态、发现清单、计划及状态规则；不请求上游。 |
| POST `/models` | model、label、family、protocol；添加全局常用模型，重复返回 409。 |
| PUT `/channels/{channel_id}/models/{model_id}` | upstream_model、protocol；修改该渠道的精确模型映射。 |
| POST `/channels/{channel_id}/fetch` | auth_kind=openai/anthropic、confirm_live=true；主动获取上游模型。结果含 ok 与固定错误分类；不回显上游错误正文。 |
| POST `/enrollment/preview` | schedule_id、items=[{channel_id,model_id}]；返回目标新增/复用/恢复/跳过明细、每批/每日新增请求数和 preview_token。 |
| POST `/enrollment` | 同预览输入并附 preview_token、confirm_live=true；原子追加目标。计划、映射或凭据已变化则 409，需重新预览。 |
| POST `/verify` | items、confirm_live=true；返回 202 和 run_id，同一目标已有未完成任务则 409。 |

路径表后六项相对于 `/api/model-coverage`。输入错误 400/422，目标不存在 404。沿用工作台鉴权与跨站限制。获取和真实测试采用界面显式勾选，对应 API 必填 confirm_live=true；打开页面、添加常用模型、保存公共渠道不构成真实请求确认。独立 channels/其他单工具模式可查看、维护清单与主动获取，单次验证及加入计划要求完整工作台或 stability 模式。

## 只读检查与验证

不读取业务库的默认检查：`python -B scripts/inspect_model_coverage.py`。检查已授权的现有数据：追加 `--data-dir /absolute/external/data`，只以 SQLite mode=ro 读取公开配置，不加载主密钥、不初始化表、不发请求。输出稳定渠道别名、脱敏主机、常用模型/协议、渠道实际模型映射、配置指纹、提取时间及 requests_sent=0；映射中的实际模型 ID 或协议变化会改变配置指纹。旧库没有常用模型相关表时展示默认目录和空映射，不创建新表。

注册清单见 [测试清单](../../docs/model-coverage-testing.md)。开发和验收只使用合成 Mock，无真实上游验证。

## 模型与协议检测入口

启用准入模块时，公共渠道及模型行提供“模型与协议检测”入口，进入同一渠道、实际模型的检测页。该页可读取或更新本模块的上游模型列表缓存，也支持临时URL和Key。列表获取与模型请求分开确认；协议结果不替代此处的定时测试、质量与长期稳定性状态。详见 [使用说明](../../docs/protocol-admission.md)。
